# M6.5 manual test (Otter news)

Setup: the dev mesh runs the M6.5 server build (`otter-server/scripts/dev-mesh.sh stop && scripts/dev-mesh.sh`, data
kept). Owner commands on the dev admin dir (`bin/otter-admin --dir .dev-mesh/admin …`, throwaway passphrase from
`scripts/dev-mesh.sh`); the dev nodes have plain `ws://` endpoints, so `manifest publish` and `announce` need
`--allow-plain`. APK for the update rows: a throwaway build with `versionCode = 7; versionName = "0.6.1"` (not committed),
copied to every dev node with `bin/otter-node apk import --config .dev-mesh/<n>.toml FILE` (`<data_dir>/apk/<sha256>.apk`).
Texts are files: `announce --ru ru.txt --en en.txt [--apk FILE --version-name 0.6.1 --version-code 7]`.
Emulator hints: see `m5-manual-test.md` (Cyrillic can't be typed, links in ≤ 60-char chunks, `uiautomator dump`).
An invite link must be typed into the field while it has focus; pressing Back with the keyboard already hidden leaves the
screen. Language: `adb shell cmd locale set-app-locales app.ottermsg --locales en-US` (and `ru-RU` back).

Result column: the 2026-11-13 emulator run (`Medium_Phone_API_35`, Android 15) against the 3-node dev mesh:
- **debug** build `app.ottermsg` 0.6.0 (6), **with** Firebase (the owner's `google-services.json` covers `app.ottermsg`)
  → «Быстрые уведомления» (FAST). The dev mesh has no FCM key, so it never pushes: a FAST phone in the background gets
  news only when it next connects.
- **staging** build `app.ottermsg.staging` (R8 release code, no Firebase → «Экономия батареи», SAVER), a second account
  registered after the first announcements — used for rows 9 and 10.

Notes from the run:
- **Bug found and fixed (2cccbff):** the news conversation was created with `last_activity_ms = now`, so a member who
  joined later saw «Новости Выдры» dated by the join time and sorted above newer chats. It is now created with the
  announcement's time (`touch` raises it to the newest as before).
- **Bug found and fixed (6160bfb):** after deleting the last announcement or revoking the key, «Новости Выдры» stayed in
  the chat list as an empty row with the old time. The chat-list query lists the news chat only while it has a message.
- **Bug found and fixed (6918f8c):** a deleted or revoked announcement stayed readable in the notification shade. The
  news notification is now cancelled when a deletion or a manifest purge removes a message. This and the previous fix
  were re-checked on the emulator (rows 5, 6) with a second dev news key (`news init` … `news revoke`); the first one
  only by its unit test (a re-check needs another fresh account).
- The emulator has a third-party app that also opens APKs, so Android showed «Open with» before the installer
  («Package installer» → «Just once»); a phone without such an app goes straight to the installer.
- The installed APK stays in `cache/apk/` until the next update download replaces it (or Android clears the cache).
- `announce` / `manifest publish` on the dev mesh need `--allow-plain` (plain `ws://` endpoints).
- Start the emulator detached (`setsid nohup emulator … &`): started from a shell that exits, it is killed with it.
- The dev news keys were removed afterwards (`news revoke`, manifest v5 without `newsKeys`); the keyring has no
  `ottermsg-news` item left.
